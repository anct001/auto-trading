# P1 — LLM sentiment feature (paper)

**Capital:** paper. **LLM role:** sentiment feature (bounded size-haircut) + decision explainer.

## Goal

Wire the slow-loop LLM as a **bounded, optional, non-vetoing** position-size haircut and prove,
**forward-only**, whether it actually helps.

## Scope

- Slow loop writes `sentiment_state.json` (schema_version, generated_at, ttl_seconds, per-pair
  `{sentiment, confidence, rationale}`) — §3.
- Fast loop reads it as an optional static feature with a staleness check; defaults to neutral
  past TTL; **must run correctly with the file absent** (Inv. 2).
- Haircut multiplier in `[FLOOR, 1.0]`, `FLOOR ≥ 0.5`. It may **never** trigger an entry, flip
  direction, or veto a trade. **Default `FLOOR = 1.0`** (logged, not acting) until validated.
- LLM explainer annotates the decision log (§12) — confident "why" ≠ correct "why" (§13.14).

## DONE-GATE

- [ ] P0 gate still holds (re-proven from clean).
- [ ] Sentiment wired strictly as a bounded modifier; absent/stale file → neutral, no halt.
- [ ] **Feature forward-validated** via ablation: system *with* vs *without* the feature in
      parallel dry-run for ≥ N_days. No historical backtest of the LLM feature is trusted
      (look-ahead leakage — §6).
- [ ] Until it demonstrably helps forward, `FLOOR` stays `1.0`.
- [ ] Dry-run green.
